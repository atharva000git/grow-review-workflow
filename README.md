# GROW Review Intelligence: n8n + MCP Workflow

Turns recent GROW app reviews into (1) an internal weekly product pulse and (2) a brokerage explainer for support, then saves them to Notion and creates a Gmail draft only after human approval.

## Flow
Form Trigger (upload CSV) → Extract From File (CSV) → Aggregate → Code (sample 25 reviews) → Basic LLM Chain (Groq, qwen) → n8n Form (approval) → If (Approve) → Code (build outputs) → MCP Client (Notion, notion-create-pages) → Gmail (Create Draft)

## How to run
1. Open the workflow in n8n and click **Execute workflow**.
2. Upload `reviews_sample.csv` in the form that opens.
3. Wait for the approval page, which displays the generated analysis.
4. Choose **Approve** or **Reject** and submit.

## Where MCP approval happens
The **n8n Form** node ("Review generated update") pauses the workflow after the analysis. An **If** node checks `Approval decision == Approve`. Only the true branch connects to the Notion MCP Client and the Gmail draft node. Reject has no connected branch, so nothing is written or drafted. The email is a draft only and is never sent.

## Fee issue identified from reviews
**Brokerage cost concern.** Two reviews in a scan of 100 fee-related recent reviews (4caf3c83-d249-4289-9b9e-c50f576c5646, d8e90096-6679-4ab6-8570-5c8b4b43b01e) say brokerage is high. The reviews show a recurring cost concern, not a proven misunderstanding of how the fee is calculated, so the explainer sticks to neutral official facts.

## Limitations (disclosed)
- The LLM (Groq free tier) was limited by token caps, so the pulse and themes come from a **25-review sample** spread across 1,200 reviews from Aug 24 to Oct 17, 2026, not all reviews. Counts apply to the sample only.
- Quotes were checked manually against the CSV; Hinglish text is kept verbatim.
- Source links and the "Last checked" date are set in the Code node, not generated by the LLM.
- Fee facts come from Groww's pricing and help pages.
